# GitKeyRouter v0.4.26 开发记录

## 目标与选择

基线为 main `ec81e34`，此前正式版本为 v0.4.25。现有程序已经具备 CLI、共享服务图和 GUI 单实例锁，因此扩展 CLI，不引入 MCP 进程、协议依赖或另一套存储逻辑。基线及仓库内不存在 `.agents/skills`，遵循 CONTRIBUTING.md。

## 实现

- 功能提交 `89fb3bb`：增加统一 JSON 查询/诊断/预览/应用输出与结构化失败，保留原有文本和 GitHub CLI 输出。
- 服务、身份、路由、Git Profile、Profile 规则支持以完整 JSON 记录保存，以及按精确 Id 删除；全部调用现有服务，沿用验证、备份和并发写入检查。
- 必须提供稳定 Id 与 `--yes`；拒绝未知参数、重复参数、错误字段、重复字段和无效枚举。参数验证早于启动恢复，避免拼错的写命令产生副作用。
- 写入继续在同步入口取得和释放跨进程 Mutex；异步服务调用完成后才释放锁，没有改变 Mutex 的线程归属。
- 修复 ConsoleBridge 对重定向 stdout/stderr 的保留，补充实际子进程 JSON 捕获、GUI 锁阻塞及参数拒绝测试。
- 在 GitServiceService 共用入口增加 Gitee 模板，复用 Generic 适配器及现有 URL/认证成功识别逻辑。
- 中英文 README 补充 AI 工作流、退出码、全部记录示例和完整替换语义。

## 服务 ID 补充修复

代码确认原服务编辑器没有 ID 输入框，保存时使用 `_original?.Id ?? _suggestedId`，因此旧服务无法改名，使用其他模板改成新主机时还会保留模板 ID。

修复提交 `f41ecd9` 新增可编辑 ID 字段、共享服务层的原子改名及 CLI `rename-service`。旧 Id 的身份、所有路由、默认路由 Id、Profile 默认服务引用一次迁移；失败不改变原配置。内置 ID 和已有 ID 冲突受保护。旧配置保持现状，只有显式编辑/改名才改变 ID。自建模板默认不再生成不透明 GUID，留空时从主机名生成。

主线程已查看用户截图，确认 Gitee 行的主机为 `gitee.com`，但 ID 保留为 `gitea-local`。回归测试直接覆盖 `gitea-local` → `gitee.com` 以及自定义目标 `gitee-work`，GUI 和 CLI 均支持此修复；Gitee 新模板默认 ID 为 `gitee.com`。本轮只修改软件和模拟数据，不修改用户电脑上的实际配置。
