# GitKeyRouter v0.4.28 开发记录

## 目标与协调方式

GUI（包括托盘）运行时允许 CLI 安全写入，页面及时更新；保留编辑窗口和 SSH 原文编辑草稿，防止旧记录覆盖新写入。

保留原有 SingleInstanceGuard，持有者仍是唯一允许修改配置的进程。GUI 运行时，CLI 在创建服务与执行启动恢复之前，通过当前 Windows 用户及会话的命名管道转发已确认写命令。GUI 使用原服务图执行；不在第二进程启动 recovery，也不把 JsonAppConfigStore 的实例内 SemaphoreSlim 误当作跨进程事务锁。没有 GUI 时，CLI 仍按原流程独占执行。旧 GUI 或其他独占进程没有管道时返回 instance_busy，不绕过锁。

GUI 的异步操作入口、编辑/预览对话框和转发命令共用非线程绑定的短期 SemaphoreSlim 操作锁，覆盖从读取与编辑，到备份、写入、验证及回滚的整个调用。已有编辑或其他操作时返回 gui_busy，不排队保存旧表单；用户完成/取消后可重试，无需退出 GUI。MainForm 执行操作期间防止退出释放进程锁。Mutex 仍在同步 Main 入口取得与释放，没有跨 await 释放 Mutex 的线程归属问题。

## 输入输出与界面

- 管道限制为当前用户，限定协议版本、已确认且经过原 CLI 参数验证的写命令、消息大小与接收超时；JSON 文件由调用方按自己的工作目录读取后转成标准输入，不让 GUI 猜相对路径。
- CLI 输入、stdout、stderr 改为可注入的逐调用流；保留原 CLI 文本/JSON 合约，不修改 GUI 进程的全局 Console。
- 不在连接断开后自动重放写入；客户端明确提示查询现状后再重试，避免把已提交但丢失响应的操作当成未执行。
- 转发结束后刷新当前页并恢复记录选择和滚动位置；切换其他缓存页时仍按原行为读取磁盘。刷新失败不把已经提交的写入改报成失败。
- 不增加覆盖草稿的后台轮询。SSH 原文编辑在开窗时冻结原始文本，后续 diff 和写入冲突检查使用该基线。

## 验证

全部新增验证使用临时路径、模拟配置与 Git 服务，不修改真实 Git/SSH 配置或凭据。

- 构建与原 CLI 64 项测试通过。
- 管道协议拒绝、损坏客户端恢复、取消时的输出隔离、操作锁释放等隔离测试 4/4 通过。
- Windows 回归包含四个真实 CLI 子进程通过 GUI 写入、GUI 列表立即刷新及选择保留，真实编辑窗口阻止 CLI 并在取消后允许重试，以及异步工具栏操作在 await 期间持锁。
